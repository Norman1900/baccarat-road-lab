# Baccarat Road Lab · v1.0

## 这是什么

面向双手机使用的百家乐历史路单分析原型：小米手机显示真人牌桌；iPhone 的 Safari 打开本网页。它对已记录的庄闲历史计算 O/R、SAP、全靴与近期结构，并按**明确写出的简化匹配条件**返回：历史候选系统、基础系统的下一手机械方向（庄/闲）、或者“不确定”。

**请准确理解**：这里的“倾向庄/闲”不是经过验证的更高胜率或正期望建议，而是所选传统规则从现有历史数据导出的方向；不能将其当成可证明的下注意见。系统的内部阈值是本项目设置的保守教学阈值，**不是 Ellis 原版的官方量化算法**。S40M3、OTB4L+、OTB4LM3 的逐手附加规则目前没有可靠完整来源，所以程序会保留“不确定”，不会杜撰。

## 下载到 iPhone 后怎样使用

需要让网站通过 HTTPS 向手机提供页面（只有 HTML 文件下载到 Files 不等于已部署的网站）。聊天环境负责制作程序包，**无法自行替你分配一个公共网站网址**。

### 发布路径A：GitHub Pages（不需要电脑，但需要 GitHub 帐号）

1. 用 iPhone Safari 登录 https://github.com/，建立一个仓库，例如 `baccarat-road-lab`，选择公开仓库。
2. 在 iPhone 的“文件”App 中解压项目 ZIP，进入解压后的 `Baccarat_Road_Lab_v1` 文件夹。
3. 进入 GitHub 仓库，选择 Add file → Upload files，选择文件夹中的 `index.html`、`app.js`、`analyzer.js`、`service-worker.js`、`manifest.webmanifest`、`icon-192.png`、`icon-512.png`（最好同次上传到仓库根目录），提交。
4. 仓库 Settings → Pages → Build and deployment → Source: **Deploy from a branch**；Branch 选 `main`，目录选 `/ (root)`，保存。
5. 等待 GitHub Pages 发布成功，然后从页面给出的链接进入。它通常是 `https://你的用户名.github.io/baccarat-road-lab/`，但必须以 GitHub 实际显示的网址为准。
6. 用 Safari 打开实际网站 → 分享 → 添加到主屏幕。完成后，Road Lab 图标可像 App 一样启动。

注意：GitHub Pages 是公网静态网站；此工具**不会自动上传牌靴或照片**。不要把含个人信息的真实截图提交到 GitHub 仓库。

官方步骤：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

### 发布路径B：Netlify Drop

官方 https://app.netlify.com/drop 支持拖放网页项目文件夹并自动获得 HTTPS 网址。但根据其说明，**需先解压 ZIP 并拖入项目文件夹**；iPhone Safari 对文件夹拖放的操作可能不如桌面浏览器方便，因此首选 GitHub Pages。

## 网页里的具体操作

### 模式 A：照片导入

1. 在 iPhone Safari 打开网页，点击“用相机拍摄 / 选择照片”。
2. 拍摄小米手机的牌桌底部。建议让 **珠盘路（六行、红蓝实心结果圆圈）**清晰、完整，并尽量正对屏幕，减少反光。
3. 照片较长时点击“聚焦下方路纸”。
4. 输入珠盘的可见列数；默认6行。
5. 按顺序点击四个位置：左上第一格中心、右上最后一列第一格中心、左下最后一行中心、右下最后一格中心。最后一列如果未排满，仍选择最后一行的理论格子中心。
6. 点击“识别网格”，逐格复核颜色。点击格子在空白、庄、闲、和之间切换。确认后导入。
7. 分析结果出现在第三部分。**目前不能直接识别一般的空心圈大路；必须选择珠盘路。**

本版的识图是纯浏览器的基础颜色网格算法，尚未针对所有机型、反光、缩放与界面皮肤进行充分测试。若校准不准确，建议使用“文字录入”。

### 模式 B：后续快速更新

每开一手，在 iPhone 上点击一次“庄 B / 闲 P / 和 T”。点击“撤销”可以修复误触。历史数据保存于本机浏览器 localStorage；清理站点数据可能导致丢失，可导出 MD/CSV 归档。

### 如何看第三部分

- **候选系统**：程序认为历史结构更符合某个传统系统；若近14手与更早历史冲突或样本太少，显示“未确定”。
- **下一手倾向**：显示该基础机械方向规则所给出的庄或闲；不确定时显示“不确定 · 暂不下注”。
- **R / O / T / OT**：在展开栏里可同时查看所有四种基础规则下一手各会选什么；这是教学对照，并非系统推荐。
- **全靴、近14手、SAP**：用于判断该候选的来源和最近是否变路。

## 路单计算口径

- B = 庄，P = 闲，T = 和。
- **和局**作为一手单独保留在原始记录中，但不改变 B/P 的连续段，也不推进 O/R 计数。需注意现实中和局会消耗实际牌值，当前模型未做牌值计数。
- O = 相邻两个有效结果不同；R = 相邻两个有效结果相同。
- 连续段按完整结果序列划分；最后一个正在进行的连续段不计入“已完成SAP”统计。
- 近期使用最多14手有效庄闲结果；前后状态冲突时不强行选系统。

## 技术说明

纯静态前端，不需要服务器后台。文件：`index.html` 页面、`app.js` UI/相机/导出、`analyzer.js` 规则引擎、`manifest.webmanifest` 主屏幕配置、`service-worker.js` 离线缓存、两张 icon 文件。版本更新需相应修改 SW 缓存名称。
